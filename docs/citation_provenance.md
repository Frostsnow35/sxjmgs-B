## 为什么做（Why）

论文中“方法名称出现过”与“该方法的公开出处已经核验并在正确位置引用”不是同一件事。技能、MCP、既有代码或模型先验可以影响检索方向，但它们既不是可供读者访问的公开文献，也不能替代作者对原始公开资料的核验。本台账据此把三类依据分开：公开方法文献、题设/接口资料和本地冻结结果；并把每条依据映射到代码和正文位置。

## 要改变什么（What Changes）

1. 问题三、四中确实调用的 MEC、逐半平面多边形裁剪和 SciPy 空间几何实现，均在同段给出经核验的公开出处。
2. 题面、模拟器说明和演练结果保留为可复核资料来源，但不伪装成公开学术参考文献。
3. 覆盖、包含关系、网格清除等本题结论只由正文推导和冻结计算验证支撑；文献只说明算法或软件事实，不承担这些结论的证明责任。

## 会影响什么（Impact）

- 三份初稿的文内引用与文末参考文献表；问题一、二不新增公开文献，因为其现有结论由本题推导和构造验证完成。
- 后续改动 `geometry.py`、`survey_design.py` 或更换数值库时，须同步更新本台账、正文引用和参考文献表。
- 本文件是团队内部的证据索引，不是竞赛论文正文；最终排版时应保留正文中的引用和文末参考文献，不必附上本台账。

### SHALL：后续执行规则与验收场景

1. **SHALL-1**：新增外部算法、软件或事实性专业结论时，必须先独立找到公开、可访问的原始或权威来源，核验元数据，并在第一次实质使用该信息的同段引用。
   **验收**：文内每个新增 `[n]` 都能在对应文末条目和本台账中找到“用途—代码/推导—支撑边界”。
2. **SHALL-2**：本地题面、接口、日志和冻结结果必须给出路径、使用位置和证据类型；不得因为其被 Git 跟踪或被工具读取，就伪称为公开参考文献。
   **验收**：所有定量结果均能回溯至 L4/L5 或明确的正文推导。
3. **SHALL-3**：公开文献不得代替本题证明。
   **验收**：删除 M1--M3 后，七点覆盖、三角格覆盖和网格覆盖的论证仍可由本文引理和公式独立阅读；删去任何一条算法描述时，不影响本题结论的逻辑有效性。
4. **SHALL-4**：未实际支撑正文的文献不得进入参考文献表；仅由技能、MCP、模型记忆或搜索摘要触发、但未独立核验和使用的资料不得引用。
   **验收**：问题一、二无外部参考文献表；问题三仅列 M1/M2，问题四仅列 M1/M3。

## 如何处理废弃或迁移（REMOVED）

- **REMOVED**：把“工具预设中可能出现的方法名称”直接写入参考文献的做法。
  **Reason/Migration**：先将其作为检索线索；只有独立核验并确认其对应实际实现/论述后，才在正文和文献表中登记。
- **REMOVED**：将本地题面、DOCX 或演练日志混列为公开学术文献的做法。
  **Reason/Migration**：改按 L1--L5 登记；未来获得稳定的官方公开链接后再补充正式电子文献条目。
