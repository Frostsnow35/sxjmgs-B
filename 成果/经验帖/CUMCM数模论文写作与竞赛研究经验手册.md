## 一、为什么做（Why）

参考论文的价值不在于记住某个题的数值答案或套用某个算法，而在于观察高质量参赛作品如何把“题目要求—数学模型—程序求解—证据—结论”连成一条可审阅、可复核的链条。本手册将这些方法转化为后续 AI 和建模者都能执行的检查项，减少以下问题：

1. 论文有模型名，但没有说明为什么适合本题；
2. 代码能运行，但结果没有固定、溯源和验证；
3. 只给最优数值，没有基线、误差、敏感性或适用边界；
4. 问题分析、模型建立、结果分析互相重复，评阅者看不见解题思路；
5. 论文写到最后才整理摘要、图表、附录和合规要求，导致数字不一致或无法提交。

## 四、最重要的底层工作流

### 4.1 总链条

> **读题拆得分点 → 判断题型与数据 → 先做可复现基线 → 建立可解释主模型 → 证明结构/降维/分层 → 选择有动机的算法 → 冻结结果 → 多角度验证 → 证据化写作 → 合规与一致性审计**

这条链条是本手册的默认顺序。若后一步发现问题，应沿依赖关系回溯，而不是只修改文字。

### 4.2 每问的“模型合同”

开始写代码前，为每一问写清楚以下内容：

| 项目 | 必须回答的问题 |
|---|---|
| 输入 | 题目给了什么数据、单位、时间范围、边界和先验信息？ |
| 输出 | 题目要求计算、预测、选择、设计还是比较什么？ |
| 目标 | 最大化/最小化/判定/拟合/估计的对象是什么？ |
| 约束 | 硬约束、软约束、物理约束、业务约束分别是什么？ |
| 假设 | 每条假设减少了什么复杂度？若不成立会影响哪一部分？ |
| 方法 | 为什么选此模型？至少保留一个合理替代方法或基线。 |
| 证据 | 用什么误差、对照、可行性、收敛或敏感性结果证明？ |
| 产物 | 结果表、图、日志、参数、代码和论文中的引用位置是什么？ |

### 4.3 三问法：决定是否使用一个模型或算法

任何模型、算法或复杂技巧进入主线前，必须回答：

1. **问题性质是什么？** 是守恒/几何/动力学、预测、分类、排序、路径、调度、随机决策，还是混合问题？
2. **数据和函数有什么特征？** 是否有单调性、对称性、单峰性、连续性、稀疏性、时序性、离散性、噪声或不确定性？
3. **为什么用它而不用替代方法？** 复杂度增加带来什么可度量收益？是否有基线、消融、误差或稳定性证据？

答不清第三问时，默认退回更简单的基线或分层模型；不要用“精度高、效率高、适应性强”替代论证。

## 五、论文写作方法沉淀

### 5.1 摘要：一页内完成“问题—方法—结果—价值”

参考论文中最稳定、最值得复用的摘要结构是：

1. 一两句交代对象和总目标；
2. 按问题一、问题二……逐问写；
3. 每问说明核心模型/处理链，而不是只罗列算法名；
4. 每问至少给一个最终可核查结果，带单位、精度和必要的条件；
5. 最后给关键词，关键词应能覆盖题型、主模型和关键求解方法。

推荐句式骨架：

> 针对问题 $k$，在……条件下，将问题转化为……；先用……建立……模型，再用……求解/验证；得到……（数值、单位、区间或决策），并通过……检查其可靠性。

摘要不应写：

- “建立了数学模型，结果见表格”而不给关键结果；
- 将尚未冻结的试算结果写成最终值；
- 只写“采用遗传算法、粒子群算法、模拟退火”等名词，不说明它们解决哪一个困难；
- 把论文意义写成没有证据的“具有重要意义、显著提升、广泛适用”。

### 5.2 问题分析：让评阅者看见思考，而不是重复题目

每一小问的问题分析至少应包含三段逻辑：

1. 题目真正要求的量和困难是什么；
2. 哪些结构、物理规律、统计特征或约束可以利用；
3. 为什么后文的模型能解决这些困难，以及本问结果如何服务下一问。

高质量分析常用的桥接方式：

- 2023 A 类参考论文：先把光学效率拆成余弦、阴影遮挡、截断、大气透射等可解释分量，再做镜场优化；
- 2023 B 类参考论文：先证明沿等深线方向具有结构优势，再递推测线间距；
- 2024 A 类参考论文：先建立螺线位置和速度递推，再把碰撞、调头路径和限速问题建立在同一递推框架上；
- 2024 B 类参考论文：先把生产流程画成决策节点和反馈循环，再计算期望利润并做不确定性分析。

### 5.3 假设和符号：每一条都必须能进入计算

有效假设应写出：

- 假设内容；
- 现实依据或题目依据；
- 它简化了什么；
- 违反它会影响哪个输出。

例如“忽略板凳厚度”只有在后文碰撞边界确实以长度、宽度和把手位置计算时才是有效假设；“天气晴朗”若没有进入光学功率或效率公式，则只是背景性陈述。

符号表建议统一列出“符号—含义—单位—首次使用位置/来源”。特别检查：同一符号是否在不同小问换含义、角度是否混用度和弧度、功率/能量/面积是否混量纲。

### 5.4 模型章节：固定“定义—公式—求解—解释”顺序

每个主模型至少包含：

1. 对象和边界的定义；
2. 变量、参数、单位和数据来源；
3. 核心公式、目标函数和约束；
4. 参数如何估计或由前问传入；
5. 算法步骤和停止准则；
6. 结果表/图及其解释；
7. 误差、局限和下一问的接口。

公式不是装饰。一个公式出现后，应能在代码或推导中找到对应实现；一个关键代码结果出现后，应能在论文中找到公式、参数和解释。

### 5.5 结果分析：使用 D-A-C，而不是复述图题

每张关键图表都按以下顺序解释：

- **D（Describe）描述**：图/表展示了哪些变量、时间、区域和单位；
- **A（Analyze）分析**：变化、峰谷、排序、误差或异常是什么；
- **C（Conclude）结论**：这对当前小问的决策或模型选择意味着什么；
- 需要时补一句限制：这一结论只在什么范围、假设或数据条件下成立。

“如图可知结果较好”不构成结果分析。必须指出模式、证据和对问题的含义。

### 5.6 模型评价：优点、缺点和改进要相互对应

建议采用三列表：

| 观察到的优点 | 对应证据 | 边界/改进 |
|---|---|---|
| 利用几何/物理结构降低维度 | 证明、递推或变量数量变化 | 若地形/路径不满足结构，需要局部化或重新拟合 |
| 模型可解释 | 公式、变量和参数来源完整 | 仍需检查参数不确定性 |
| 算法计算效率可接受 | 运行时间、迭代次数、误差 | 说明规模增大后的复杂度 |

不要把“适应性强、准确性高、应用广泛”作为无证据的优点；不要把“忽略现实因素”写成唯一缺点而不说明影响方向和改进路径。

## 六、按题型沉淀的研究方法

### 6.1 A 类：机理、物理、几何和工程反演

推荐主线：

1. 明确坐标系、边界、单位和守恒/几何/运动规律；
2. 建立可复现的评估或反演模型；
3. 把复杂对象拆成可解释子模型；
4. 寻找对称性、单调性、单峰性、局部性或无量纲关系；
5. 在证明或降维后再优化；
6. 用物理量纲、极限情形、数值对照和敏感性检查。

参考论文中的可复用模式：

| 题型特征 | 可借鉴做法 | 不能机械复制的部分 |
|---|---|---|
| 光学/能量传递 | 先拆效率分量，再用光线追迹或栅格化计算遮挡/截断 | 网格精度、光线数量、太阳模型必须重新收敛检查 |
| 螺线/多刚体运动 | 龙头或首节点参数化，后续节点位置/速度递推 | 碰撞对象、路径分段和速度上限随题目变化 |
| 声学/地形测线 | 几何推导覆盖宽度，证明方向结构，再递推间距 | 重叠率定义、坡面拟合和边界处理必须核对题意 |
| 信号/参数反演 | 预处理—特征定位—物理反演—多组数据合并—误差区间 | 滤波和峰谷规则不能凭经验硬套 |

机理题的第一问往往决定后续上限：如果基础评估模型没有做对，后续优化只是在放大错误。

### 6.2 B 类：路径、调度、生产与随机决策

先区分：

- 连续几何优化：优先几何证明、动态规划、递推、线性/整数规划；
- 离散决策与不确定性：优先状态/决策树、期望收益、概率约束、随机优化或仿真；
- 路径规划：先确定覆盖/可行性，再优化总长度、转弯、重叠和连续性；
- 多阶段生产：显式写检测、装配、拆解、退换等反馈循环，不要把循环过程隐藏在黑箱仿真中。

随机仿真必须说明：随机变量及分布、样本量、随机种子、估计量、置信区间/误差和收敛判断。启发式算法必须说明编码、适应度、参数、停止条件和基线；否则“算法优化”只是不可复核的标签。

### 6.3 C 类或数据驱动题：从描述走向决策

推荐三段链：

> 数据清洗与质量检查 → 统计检验/结构发现 → 预测与误差评估 → 决策优化 → 情景/稳健性分析

具体要求：

- 异常、缺失、退货、无销量和打折数据处理规则要写；
- 时间效应、趋势、周期、节假日和价格效应应分开讨论；
- 预测必须有训练/验证划分、指标、基准模型和误差；
- 预测结果要进入补货、定价、种植、库存或其他可执行决策；
- 不确定性要通过情景、参数扰动、分布假设或置信区间进入决策，而不是只在结尾口头说“模型鲁棒”。

## 七、算法选择与复杂度管理

### 7.1 默认优先级

1. 能解析推导就先推导；
2. 能证明方向、对称性、单调性或单峰性就先证明；
3. 能降维、分层、分区、分治就先做；
4. 用简单基线确认口径和数量级；
5. 再使用数值搜索、随机模拟或启发式优化；
6. 用替代方法、重复运行或局部扰动检查主结果。

这不是“拒绝复杂模型”，而是要求复杂度有来源、有收益、有证据。

### 7.2 常见算法的使用合同

| 方法 | 使用前必须证明/说明 | 至少配套的验证 |
|---|---|---|
| 二分/三分/黄金分割 | 单调、单峰或可接受的局部单峰区间 | 网格扫描、邻域比较、停止误差 |
| 网格/栅格化 | 离散误差与计算量的权衡 | 网格加密收敛、与解析/粗基线对照 |
| 蒙特卡洛 | 随机机制、样本量和估计量 | 固定种子、多次重复、标准误/置信区间 |
| 遗传/粒子群/蚁群 | 解编码、适应度、约束处理和参数 | 多种子、基线、收敛曲线、可行性检查 |
| 模拟退火 | 邻域、温度、降温和停止规则 | 重复运行、最优/均值/方差、基线 |
| 最小二乘/曲面拟合 | 误差模型、拟合区域和阶数 | 残差、交叉验证或分区对照 |
| 时间序列/机器学习 | 时间切分、防止泄漏、特征和预测范围 | 基线、验证误差、滚动预测或情景测试 |

### 7.3 复杂模型的反对过度工程化检查

如果出现以下任一情况，应暂停增加模型：

- 论文同时出现多个作用相同的群智能算法，但没有比较；
- 算法参数由“经验设置”给出，没有敏感性或收敛证据；
- 主模型比基线复杂很多，但结果差异没有量化；
- 模型名称复杂，代码或伪代码无法解释每一步；
- 只报告单次最优值，不报告随机性、失败运行或可行性；
- 把拟合/预测误差直接当作最终决策的经济或物理误差。

## 八、验证、稳健性与结果冻结

### 8.1 四种验证不要混为一谈

| 类型 | 回答的问题 | 例子 |
|---|---|---|
| 实现正确性 | 代码是否按公式运行？ | 单元测试、极限值、量纲、手算小例 |
| 数值误差/收敛 | 离散化、迭代或随机估计是否稳定？ | 步长减半、网格加密、样本量增加 |
| 模型合理性 | 结果是否符合已知规律？ | 对称性、单调性、守恒、物理极限 |
| 决策稳健性 | 参数/数据扰动后结论是否仍可用？ | 灵敏度、情景模拟、置信区间、替代模型 |

一条“模型正确”的结论至少应指出使用了哪一种证据，不要用一张好看的图替代全部验证。

### 8.2 结果冻结规则

在论文写作前，建立 `output/results/` 中的结构化结果文件，并记录：

- 输入文件和版本；
- 代码提交/文件时间；
- Python/Matlab 版本与主要依赖；
- 随机种子；
- 参数配置；
- 运行命令、日志和运行时间；
- 结果表、图源数据和图形脚本。

结果、表格、图和摘要应只从冻结文件读取。任何数据、公式、参数或算法变化都要标记下游论文和图表为“待重算”，不得沿用旧数字。

## 九、72 小时比赛研究推进法

时间表是模板，具体以当届比赛和团队状态为准。

| 阶段 | 研究主线 | 必须留下的产物 |
|---|---|---|
| 0–4 小时 | 三人独立读题、列得分点、判断题型并定题 | 题目拆解表、候选路线、风险清单 |
| 4–12 小时 | 做基线、统一符号和数据口径、完成前两问骨架 | 模型合同、基线结果、问题分析初稿 |
| 12–36 小时 | 主模型和代码循环，写作同步开始 | 可运行脚本、日志、阶段结果、图表源数据 |
| 36–52 小时 | 收口后续问题，做验证、敏感性和替代方法 | 冻结候选结果、误差/收敛/可行性证据 |
| 52–64 小时 | 论文整合、摘要、评价、参考文献和附录 | 完整草稿、数字溯源表、代码清单 |
| 最后 4 小时 | 只做减法和合规审计 | PDF/Word、支撑材料、打开测试、提交确认 |

团队协作纪律：

- 建模者必须能向写作和编程成员口头解释每个主公式；
- 编程者每个结果都保存结构化文件，不把终端输出作为唯一证据；
- 写作成员负责评阅视角，但不替数学成员确认未经核实的数字；
- 每次同步只回答“完成了什么、卡在哪里、下一步需要谁的什么产物”；
- 超过 30 分钟无法解决的分歧，写出方案、假设和代价后再投票或请外部视角审阅；
- 决赛后段不重构大代码，只允许小范围参数和错误修复，并重新冻结结果。

## 十、论文交付与合规审计

比赛当年规则优先。按当前资料中的历年规范，提交前至少检查：

- 摘要专用页是否不超过一页；
- 正文结构是否清楚，是否误加不必要的目录；
- 论文、代码、结果表和支撑材料是否相互一致；
- 所有关键数字是否能追溯到题目、前问、公式推导或冻结结果文件；
- 图表坐标轴、单位、图注、编号和正文引用是否齐全；
- 公式中的符号、单位、角度制和代码实现是否一致；
- 参考文献是否真实、可查、格式一致并在正文对应引用；
- 论文、附录和代码是否泄露队伍身份信息；
- PDF 能否打开、页码是否连续、文件大小和命名是否满足当年要求；
- 提交前是否留出服务器、上传和意外故障余量；
- AI 工具的使用是否符合当届官方规定，且队员能为每一行公式、代码和结论负责。

查重和相似度阈值、电子版规格、附录要求等属于易变规则，必须以当届官方通知为准，不把本手册的历史摘要当作最终依据。

## 十二、常见失败模式与修正动作

| 失败模式 | 具体症状 | 修正动作 |
|---|---|---|
| 算法堆砌 | 摘要和正文出现多个算法，但每个算法的作用边界不清 | 删除同功能算法；保留基线、主算法和必要的验证算法 |
| 伪最优 | 单次随机运行的最好值被写成“全局最优” | 改为“在给定范围/参数下得到的最优候选”，补多种子和基线 |
| 结果先行 | 先写漂亮结论，再寻找公式解释 | 从冻结结果和代码回写，无法溯源的数字删除或标 TODO |
| 只验证代码 | 代码无报错就称模型正确 | 增加极限、量纲、理论规律、替代方法和敏感性验证 |
| 图表无结论 | 图中有曲线，正文只说“如图所示” | 按 D-A-C 写描述、机制、结论和边界 |
| 假设空泛 | “忽略一切影响”“数据真实有效”但不说明影响 | 为每条假设补依据、计算入口和违反时的后果 |
| 跨问断链 | 每问像独立论文，前问结果没有传给后问 | 画问题依赖 DAG，标出参数继承和结果接口 |
| 单位/口径漂移 | m/cm、度/rad、利润/收益、平均/总量混用 | 建变量字典和结果 schema，运行前后自动核对 |
| 过早写作 | 最后一晚才开始整理模型和图表 | 写作队员从第一天同步，结果一出立即登记证据 |
| 规则误用 | 把转载“评分细则”当官方硬规则 | 标注来源等级，比赛当年重新核对官网和赛区通知 |

## 十三、后续 AI 执行时的最小指令集

遇到新的 CUMCM 题目或论文任务，AI 默认执行：

1. 先读取本手册、项目 `AGENTS.md` 和已有计划/状态文件；
2. 把题目逐问拆成输入、输出、目标、约束、数据和依赖；
3. 按题型提出至少两个候选方法，并先做简单基线；
4. 所有随机方法固定种子，保存日志和结构化结果；
5. 每个重要结论绑定公式、代码、数据或推导证据；
6. 写论文前冻结数字、图表和参数；
7. 审查模型选择三问、复杂度收益、验证证据、局限和来源等级；
8. 在最终交付前逐项检查摘要、正文、图表、代码、附录、匿名和当年规则。
