# CUMCM2026 数模工作区

本文件是 `E:\CUMCM2026` 的项目级 AGENTS 配置，面向全国大学生数学建模竞赛（CUMCM）作品工作区。除非当前任务明确涉及 MoonCARE 或其它项目，否则以本文为准；与通用用户级 AGENTS 冲突时，以本项目工作区规则为准。

## 目标与边界

- 当前是“备赛 + 正式赛题执行”工作区，主要使用 Python，暂不对论文格式做硬性要求。
- 用户是最终建模者；模型选择、假设口径、数据取舍和最终提交由用户确认。AI 负责分析、编码、验证、写作支撑，不替用户虚构参赛事实。
- 凡出现结果、引用、参数、图表，必须可追溯；无法验证的内容必须明确标记为“推测/TODO”，不得伪装成已验证结论。
- 未获得用户明确同意前，不对外提交、不联网下载参赛题目以外的数据、不安装额外权限工具、不修改用户其它项目。

## 协作与交互

- 用中文交流，代码、变量、文件名可保留英文。
- 需求含糊但影响建模口径时，先列 2-3 个候选解释及其代价，再让用户选；不要反复问无关问题。
- 正式比赛时间内，每阶段默认产出可审阅产物；用户可随时要求只做“诊断/讨论”而不改文件。
- 不要因为时间紧张跳过验证；也不要为了显得复杂而堆模型。
- 关于竞赛规则、AI 使用声明、允许工具与提交格式，AI 不确定时应提示用户以当届官方通知为准。

## Python 规范

- 目标 Python 3.10+；当前机器为 Python 3.12，运行前用 `python -V` 确认。
- 公共依赖写入 `requirements.txt` 并固定主要科学库版本；新依赖必须说明用途。
- 可复用逻辑放 `src/`，单次实验放 `scripts/`，主程序提供 `if __name__ == "__main__"` 入口。
- 函数添加类型注解与简短 docstring；关键步骤写 `logging` 日志，避免用 `print` 传递唯一结果。
- 任何随机算法/采样固定 `SEED`，把运行命令、输入文件、随机种子和输出文件写入实验记录。
- 结果文件统一使用结构化格式，例如 JSON/CSV，字段名稳定、可机器读取；论文数字必须来自 `output/results/`。
- 修改公式、算法或评价口径时，同步更新模型说明文档，避免代码与文档漂移。

## 建模纪律

1. 先判题型再选模型。A 类机理题使用 `$cumcm-a-mechanism-modeling`；B 类运筹优化题使用 `$cumcm-b-optimization`；混合题先逐问标注任务类型。
2. 模型要回答“为什么用、数据是否满足、缺陷是什么、如何验证”，而不是罗列算法名词。
3. 假设逐条编号，说明合理性、影响范围与若违反时的后果。
4. 公式、变量、单位在正文与代码中一致；命名冲突在写作前清理。
5. 求解输出必须包含可行性/误差/收敛/最优性差距中的至少两项可验证证据。
6. 灵敏度、稳健性与模型比较只针对“已求得且已核实”的结果。

## 完成标准

每个子问题只有满足以下条件才能算“完成”：

- 输入输出口径明确，且与题目逐字对应；
- 求解代码在本机可运行，关键脚本已执行并留下日志/结果文件；
- 数值、图、表格均能从结果文件溯源；
- 至少完成一次简单反证或替代方法对照；
- 假设、局限、灵敏度结论写入模型说明；
- 未经用户确认的方案不得标记为最终方案。

提交前按归档中的 `原始仓库_20260912\prompts\cumcm-phased-prompts.md` 从 Phase 5 重新执行一次“证据链 + 全文审阅”。
